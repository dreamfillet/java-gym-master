# java-gym-master
Техническое задание. Gym master
Представьте, что вы узнали новость: недалеко от вашего дома открылся новый гимнастический зал для детей и взрослых. Когда вы пришли туда, то узнали, что хозяин этого зала — ваш старый знакомый, который когда-то начинал учиться программированию вместе с вами, но потом бросил. Он рассказал вам, что написал программу на Java для управления своим залом и что она ему очень помогает, но некоторые функции у него реализовать никак не получается. 
Особенно большие сложности возникли с хранением расписания и его обработкой. Ваш приятель очень жалеет, что бросил обучение программированию и не смог дописать программу до конца, и просит вас о помощи. 
Итак, ваше задание в этом спринте — доработать программу для учёта работы гимнастического зала таким образом, чтобы с её помощью администраторы могли легко выполнять свои задачи.
Подготавливаем ветку
В этом задании вы откажетесь от привычного процесса разработки в главной ветке. Теперь вы будете выполнять каждую проверочную работу в отдельной ветке.
Для выполнения задания текущего спринта создайте в локальном репозитории ветку с названием develop.
Постановка задачи
Для начала приятель рассказал про модель работы своего зала и про то, какие основные сущности он определил в своём приложении. 
В зале проводятся тренировки для детей и взрослых. Все занимаются в группах Group — каждая из них соответствует определённому типу тренировок и определённому возрасту. Например, группой будет «акробатика для детей 10–12 лет». Занятия каждой группы могут проходить несколько раз в неделю. Так, указанная группа по акробатике может заниматься по понедельникам, средам и пятницам в 18:00, а также по выходным в 12:00.
Каждое занятие проводится определённым тренером Coach. При этом в одной группе тренировки могут вести разные тренеры. Так, по понедельникам, средам и субботам акробатику может вести тренер Измайлов К.В., а по пятницам и воскресеньям — Семёнов В.К. 
Клиенты могут заниматься в любой группе сколько угодно раз в неделю, но есть обязательное условие — они должны соответствовать возрасту участников. То есть дети не могут посещать взрослые группы, а взрослые — детские.
Тренировки проходят по расписанию Timetable, которое составляется администрацией на неделю. Это набор занятий TrainingSession, каждое из них соответствует тренировке определённой группы, которую проводит конкретный тренер в определённое время.
Составляем расписание
Приятель рассказал вам о своих проблемах, которые у него пока не получается решить. И первая из них — хранение расписания тренировок. На данный момент ему не удалось придумать, как хранить расписание внутри программы так, чтобы с ним было удобно работать. Поэтому расписание сейчас составляется вручную на листке бумаги, и администраторы пользуются этим листком, когда консультируют новых клиентов о доступных тренировках и времени занятий.
Конечно, это очень неудобно — сложно найти нужную тренировку, возникает много недоразумений. А при каждом изменении расписания его приходится переписывать. Поэтому приятель попросил вас придумать, как хранить расписание внутри программы.
Чтобы понять, как именно должно храниться расписание, нужно понять, как именно оно будет использоваться и какие есть при этом ограничения.
Администраторы чаще всего выполняют с расписанием следующие задачи:
Получение всех тренировок, упорядоченных по времени начала, за конкретный день недели. Утром, придя на работу, администратор распечатывает список всех тренировок на сегодня — с утра и до вечера — и вывешивает его на доске, чтобы все посетители могли его увидеть. Кроме того, часто новые посетители звонят и спрашивают, какие есть тренировки сегодня. Тогда этот список тоже пригодится. Так как первый клиент может прийти почти сразу за администратором и нужно обязательно успеть распечатать список, то этот запрос должен выполняться очень быстро — требуемая алгоритмическая сложность O(1).
Получение всех тренировок, начинающихся в конкретное время, за конкретный день недели. Самый частый вопрос, который клиенты задают администратору по телефону: «Какие есть тренировки сегодня в такое-то время?» И администратор должен очень быстро ответить на этот вопрос. Для этого запроса допустима сложность O(log(n))  или быстрее.
Добавление новой тренировки в расписание. Новая тренировка может быть добавлена для любого дня недели и любого времени. При добавлении администратор выбирает группу и тренера. Так как это обычно происходит заранее, это не столь требовательная по времени выполнения операция, и ограничения относительно её алгоритмической сложности отсутствуют.
Ваша задача теперь — придумать структуру данных для хранения расписания так, чтобы выполнялись все перечисленные выше требования.
Реализуйте хранение расписания и методы getTrainingSessionsForDay и getTrainingSessionsForDayAndTime. Не забудьте учесть, что в одно время может начинаться сразу несколько тренировок!
Протестируйте свою реализацию с помощью юнит-тестов. Для этого доработайте существующие тесты, а также добавьте не менее трёх новых — подумайте, какие случаи стоит рассмотреть.
Считаем тренировки
С основными запросами администраторов разобрались, осталось совсем немного — помочь им в решении ещё одной задачи. Достаточно часто администраторам нужно посчитать, сколько занятий в неделю ведёт каждый из тренеров. Эта информация нужна, например, для начисления тренеру зарплаты. Поэтому вам нужно добавить в класс Timetable ещё один метод, который будет отвечать на этот вопрос.
Добавьте метод getCountByCoaches в класс Timetable. Метод должен для каждого тренера возвращать его количество тренировок в неделю, при этом тренеры должны быть упорядочены по количеству тренировок по убыванию — то есть первыми возвращаться будут тренеры, которые проводят больше всего занятий. Можно считать, что связка Ф. И. О. уникально идентифицирует тренера. Требования к алгоритмической сложности этого метода отсутствуют, тип возвращаемого значения также может быть любым — главное, чтобы он содержал требуемые данные.
Добавьте также юнит-тесты для нового метода — не менее трёх тестов. Тесты должны позволять убедиться, что метод корректно работает с разными входными значениями.
На этом всё! Ваш приятель вам очень благодарен — теперь администраторы будут гораздо меньше времени тратить на рутинные задачи и больше общаться с клиентами, а клиенты всегда смогут получить корректную и актуальную информацию.
